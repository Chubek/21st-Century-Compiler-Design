## Implemented artifacts

All new implementation files are in `example-code/lua-toolchain/`:

- `common.h`: checked buffers, explicit little-endian serialization/access,
  bounded ownership registry, I/O, Lua setup, and ELF helpers.
- `luaas.c`: Lua preprocessing, assembly parser, x86-64 encoder, symbols/fixups,
  local-first symbol serialization, ELF64 ET_REL writer.
- `luald.c`: ELF input validation, Lua-map validation, local/global/weak
  resolution, section placement, checked RELA application, sorted PT_LOAD
  emission, static ELF64 ET_EXEC writer, and placement report.
- `demo.lua`, `answer.lua`, `hello.lua`, `map.lua`: separately assembled program,
  external definition, generated byte data, and executable memory-map policy.
- `zero-check.s`: GNU assembler fixture testing PLT32, RIP-relative addressing,
  and runtime BSS zero fill through the teaching linker.
- `dynamic-lib.c`, `dynamic-main.c`: a separate host-loader/TLS experiment.
- `build.sh`, `test.py`, `checks.py`: builds, executable/differential tests,
  and independent manuscript-example computations.
- `README.md`, `SOLUTIONS.md`: complete supported contracts and forty answers.

Neither C tool shells out to another assembler or linker to implement its work.
GNU tools are independent verification producers/consumers.

### Native results

The demo's first text contribution is 31 bytes at `0x401000`; the second begins
at `0x401020` after 16-byte alignment and contributes six bytes. The loop PC32
field is -12, the external call PC32 field is 10, and the initialized pointer
contains `0x401020`. Code has file/memory extent 38; data has file extent 8 and
memory extent 48. The linked program exits **42**.

The same assembler objects linked by GNU ld also exit 42. A restricted GNU as
object linked by luald reads its zero-filled BSS and exits 37. The Lua-generated
hello program prints `Lua maps, ELF runs.` and exits zero at two code origins.
The separate host-loader experiment observes independent per-thread counter
sequences 37,38 under both GCC and Clang.

## Source and citation verification

Reference extracts were used read-only and no source passages, examples, or
exercises were copied into the new chapters.

- `sources/assemblers-book.txt` is readable. Its contents cover source-line
  structure, forward references, sections, relocatable expressions, macros,
  and assembler organization. David Salomon's author page confirms *Assemblers
  and Loaders*, Ellis Horwood, February 1993, ISBN 0130525642:
  <https://www.davidsalomon.name/assem.advertis/AssemAd.html>.
- `sources/leveine-linkers-and-loaders.txt` contains only page-break characters.
  It was not treated as readable evidence. Levine's author site verifies the
  book's identity, October 1999 publication, publisher, ISBN, and errata:
  <https://linker.iecc.com/>. The book is a further-reading pointer, not a claim
  that the unusable local extract was read.
- Official generic ELF documentation was consulted for sections, symbols,
  relocations, loading, and runtime metadata:
  <https://gabi.xinuos.com/elf/>.
- The archived AMD64 ABI draft's title page and relocation table were checked:
  draft 0.99.6, July 2, 2012, edited by Matz, Hubička, Jaeger, and Mitchell:
  <https://refspecs.linuxfoundation.org/elf/x86_64-abi-0.99.pdf>.
  This is cited as that specific draft, not as the newest ABI revision.
- GNU's official linker manual supplies archive/script, memory-region, and
  retention-policy references: <https://sourceware.org/binutils/docs/ld/>.
- Lua's official 5.4 manual supplies embedding, string, integer, and table rules:
  <https://www.lua.org/manual/5.4/manual.html>.
- Local LLVM TableGen records were queried for the distinction between MOV64ri
  and MOV64ri32. Actual encoding verification uses GNU as byte comparison.

Six verified bibliography entries were added, preserving key order. No new
citation or technical TODOs were introduced by this expansion.

## Scope of the evidence

The native tools implement the documented instruction/object subset and static
link mode. Archive extraction, relaxation, and section GC have separate small
chapter models, not implementations inside the C toolchain. Dynamic linking/TLS
uses the host loader experiment. LTO, thunks, general memory operands, arbitrary
assembler expression algebra, debug/unwind emission, and general C runtime
startup are explanatory topics or future extensions, not claimed tool features.

Lua executes as an ordinary trusted build script with standard libraries. The
tools do not offer a Lua execution-time quota or sandbox. The bounded C tables,
checked arithmetic, and tests establish their stated contracts and exercised
cases, not a proof for every possible input.

LuaLaTeX and a complete page-by-page review of the entire older manuscript were
not run. Earlier textbook-wide technical/citation obligations remain recorded
in the review documents. No changes were made to reference extracts or vendored
tooling under `PebbleIR/`.
